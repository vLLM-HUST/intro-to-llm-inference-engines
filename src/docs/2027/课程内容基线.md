# 《大模型推理系统与实践》课程内容基线

本文档统一 2027 年八讲主课、课程速览和 MOD 项目材料的术语、算例、论文出处与课程边界。

## 一、正式名称与版本定位

- 中文正式名称：《大模型推理系统与实践》
- 英文正式名称：LLM Inference Systems and Practice
- 英文课程介绍：模型原理导向的两小时快速入口，同时覆盖服务系统主线
- 中文课程介绍：系统问题导向的两小时快速入口，同时补齐必要模型基础
- 八讲主课程分 8 次授课，每次 2 节，共 16 节。第 1–6 节讲必要原理，第 7–8 节启动 MOD 项目，第 9–16 节实施、联调、评测、复现与答辩。见[授课安排](课程安排.md)。
- 每人必做一个 vLLM-HUST 引擎 MOD，可另做一个 RIDE Control Plane 插件，最多加 30 分。分项与提交节点见[课程考核与评分标准](../../site/tutorials/assessment/index.html)。

## 二、统一知识主线

所有版本都围绕一次请求的完整生命周期展开：

1. 文本经过聊天模板和分词器变成 token id。
2. 请求进入等待队列，调度器分配 token、KV 和执行预算。
3. Prefill 处理已有上下文，产生首批 KV 状态和首 token 所需的 logits。
4. Decode 每次通常推进一个新位置，读取历史 KV，生成并追加新状态。
5. 采样器选择下一个 token，服务端流式返回结果。
6. 请求在完成、取消、超时或失败后释放运行时状态。
7. 系统通过逐请求时间戳、队列状态和资源计数器验证优化效果。

## 三、统一术语与统计口径

| 术语 | 课程统一定义 | 必须同时报告 |
| --- | --- | --- |
| Token | 分词器产生的离散单元，可能是单词、子词、字符或字节片段 | 分词器与聊天模板 |
| TTFT | 请求到达到首个输出 token 可用的时间 | 起止事件、单位、并发负载 |
| TPOT | 首 token 之后，相邻输出 token 间隔的统计量 | 聚合方法、是否排除首 token |
| 端到端时延 | 请求到达到请求完成的总时间 | 输入/输出长度与停止条件 |
| Throughput | 单位时间完成的请求数或生成的 token 数 | 单位、统计窗口、失败请求处理 |
| Goodput | 单位时间内满足既定 SLO 的有效完成量 | SLO、单位、窗口、样本数 |
| P50/P95/P99 | 按明确分位数算法从逐请求样本计算的统计量 | 样本数与分位数算法 |
| KV Cache | 各层注意力为已处理 token 保存的 K/V 派生状态 | 模型版本、精度、层数、KV 头数、头维度 |

课程默认采用 nearest-rank 讲解离散分位数。使用 NumPy、Pandas 或监控系统时，必须注明软件采用的插值方法。

## 四、统一算例口径

### KV 容量

若模型有 32 层、8 个 KV 头、头维度 128，K/V 均保存，数据类型为 2 bytes，则每 token 的 KV 容量为：

`32 × 2 × 8 × 128 × 2 bytes = 131072 bytes = 128 KiB`

8192 token 约占 `1 GiB`。该估算不包含块元数据、对齐和碎片。

### KV 传输

- 4 GB 数据经过 25 GB/s 链路，理想下限为 160 ms。
- 4 GiB 数据经过 25 GB/s 链路，理想下限约为 172 ms。

二者不得混写。真实时间还包括协议、同步、排队和软件栈开销。

### Goodput

若同一 5 秒测量窗口内完成 10 个请求，其中 8 个满足 2 秒 SLO，则该窗口的请求吞吐为 2 requests/s，goodput 为 1.6 requests/s。只写“吞吐 10、goodput 8”属于缺少单位和统计窗口。

## 五、状态概念边界

- KV Cache 必须跨自回归解码步保留。
- 是否跨对话轮次复用 KV 取决于会话路由、前缀缓存和模型版本等条件，并非所有服务都默认保留。
- KV Cache、检索文档和长期对话记忆都可以从“状态管理”角度分析，但三者不是同一种对象。它们的生成方式、复用键、失效条件、一致性和安全边界不同。
- 课程将三者并置时，必须明确这是系统分析框架，而不是统一的运行时实现。

## 七、课程内部案例

KV-Delta、Segment Reuse、Tiered KV Cache、MLP Materialization、Semantic MapReduce 和自适应 Decode Backend 当前作为课题组内部实验或教学假设案例使用。课件必须遵守以下规则：

- 标题明确写“课程研究案例（内部实验）”或“教学假设案例”。
- 数字必须给出实验包、硬件、模型、工作负载和运行日期，否则只讨论方法，不报告收益。
- 不得使用会议名称、论文措辞或“研究已经证明”等表达暗示案例已经发表。
- 负结果可以用于教学，但必须保留失败运行、比较基线和有效性边界。
