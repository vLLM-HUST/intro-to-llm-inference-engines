推理流程图解

第 2 讲配套阅读。从文本输入到流式返回，跟踪一个推理请求。

一次自回归请求的执行路径

  1. 分词与调度Tokenizer 将消息编码为 Token ID。调度器按 Token 和 KV 块预算安排请求。
  2. Prefill 与首 Token模型处理输入、缓存各层 KV，并根据最后位置的 logits 采样首 Token。
  3. Decode 循环每轮读历史 KV，为当前输入位置追加 KV，再预测下一个 Token。调度器可以在轮次间调整批次。
  4. 流式返回增量解码已生成的 Token。达到停止条件后结束请求并释放其 KV 引用。

TTFT 从客户端发出请求计到收到首个内容 Token。TPOT 是首 Token 后的平均输出间隔。Goodput 只计单位时间内成功且达到服务目标的请求。

常见优化

  • KV 分页分配可减少碎片，前缀缓存可复用重复上下文。GQA、MQA 和缓存精度会影响每 Token 的 KV 占用。
  • FlashAttention 通过分块减少注意力计算的 HBM 读写。
  • 推测解码先生成草稿，再由目标模型验证。第一次拒绝时，算法采样替代 Token，丢弃其余草稿，并从新的前缀继续。
