# 实验一：最小运行与代码地图

## 一、实验课定位

这是 nano-vLLM 实验课的第一节，目标不是马上修改复杂逻辑，而是让学生在一次完整课堂里完成三件事：

1. 跑通一次最小推理请求。
2. 找到请求进入、执行和返回的主路径。
3. 建立后续所有实验都会复用的代码地图。

本节实验对应课程前半部分的导论、工作负载与指标、运行时架构基础内容，也是后续请求生命周期、调度和 KV 状态实验的前置课。

## 二、本节实验目标

完成本节后，学生应能够：

- 说清一次最小请求从哪里进入系统。
- 指出哪个对象首先真正持有请求状态。
- 区分请求入口、调度循环、模型执行和结果返回四类职责。
- 用最小日志支撑自己的代码路径判断。

## 三、课前准备

### 1. 先修要求

- 已了解 Transformer 推理的基本过程。
- 知道 prompt、token、max tokens、TTFT 这些基本术语。
- 具备最基本的 Python 运行能力。

### 2. 本节使用材料

- 理论配套：`tutorials/nano-vLLM实验与Tutorials/Tutorial_01_最小运行与代码地图.md`
- 教学代码：`code/nano-vllm-hust/`
- 参考入口：`code/nano-vllm-hust/example.py`
- 参考路径：`code/nano-vllm-hust/nanovllm/llm.py`
- 主控制路径：`code/nano-vllm-hust/nanovllm/engine/llm_engine.py`
- 作业包：`code/nano-vllm-hust/assignments/tutorial_1_spring-2026/`

### 3. 教师课前检查

上课前建议教师或助教确认：

- 学生能访问教学仓库。
- 本地模型路径或教学环境已准备好。
- 至少有一条可以直接运行的最小命令。
- `example.py` 可以在教师机器上成功演示。

## 四、建议课时安排

- 10 分钟：说明实验目标和本节只关注的系统问题。
- 15 分钟：教师演示最小运行。
- 25 分钟：学生独立建立代码地图。
- 20 分钟：学生追踪最短调用链并补最小日志。
- 15 分钟：全班讨论“第一个控制点”究竟在哪里。
- 5 分钟：说明提交要求和下节衔接。

## 五、本节只回答一个核心问题

一次请求从哪里进入系统，经过哪些关键对象，又在哪里返回结果？

注意，本节不要求学生回答“为什么性能更好”或者“调度如何优化”。本节只建立结构，不做机制推断。

## 六、课堂实验步骤

### 步骤 1：运行一次最小请求

要求学生完成以下动作：

1. 打开 `code/nano-vllm-hust/example.py`。
2. 确认模型路径、运行环境和依赖可用。
3. 运行一次单请求或双请求的最小生成示例。
4. 记录输入 prompt、输出长度和是否成功返回。

建议记录模板：

```text
运行命令：
模型路径：
输入 prompt：
输出 token 数：
是否成功返回：
异常信息（如有）：
```

### 步骤 2：建立最小代码地图

要求学生不要泛读整个仓库，而是只定位以下五类对象：

1. 请求入口。
2. 请求对象或状态对象。
3. 调度器或主循环。
4. 模型执行器。
5. 结果返回位置。

建议填写表格：

| 系统职责 | 文件 / 类 / 函数 | 你的判断依据 |
| --- | --- | --- |
| 请求入口 |  |  |
| 请求状态 |  |  |
| 调度循环 |  |  |
| 模型执行 |  |  |
| 输出返回 |  |  |

### 步骤 3：追踪最短调用链

从 `example.py` 出发，要求学生写出一条 6-10 步的最短调用链。允许函数名不完全一致，但职责必须自洽。

示例格式：

```text
example.main -> LLM.generate -> ... -> response
```

### 步骤 4：加入最轻量日志

只允许在三个位置加日志：

- 请求进入点。
- 执行开始点。
- 结果返回点。

日志建议包含：

- `request_id`
- `prompt_len`
- `max_tokens` 或 `output_len`
- `timestamp`

目标是证明调用链，而不是把运行时打满调试输出。

## 七、课堂讨论问题

本节讨论不看谁读了更多文件，而看谁能把判断说清楚。

要求学生回答：

1. 系统里第一个真正拥有请求的对象是谁。
2. `LLM` 是控制点，还是对更深层对象的封装入口。
3. 输出返回之前，最后一次关键状态更新大概发生在哪里。

## 八、常见错误

- 一上来就看所有文件，最后主线反而更乱。
- 只写目录截图，不写职责判断。
- 只说“请求进入 engine”，但说不清进入前后对象发生了什么变化。
- 日志插桩过多，结果无法从输出中提取主路径。

## 九、课后提交要求

每位学生或每组至少提交以下内容：

1. 一张代码地图表。
2. 一条最短调用链。
3. 一段最小日志摘录。
4. 一段 300-500 字说明，回答“当前看起来第一个控制点在哪里”。

## 十、评分重点

- 是否真的定位了五类核心职责。
- 最短调用链是否闭合、自洽。
- 日志是否能支撑你的路径判断。
- 说明文字是否回到“控制点”而不是停在目录描述。

## 十一、与后续实验的衔接

本节交付物会直接用于：

- 实验二的请求生命周期时序图。
- 实验三的调度控制点定位。
