# 实验五：指标观测与最小复现实验

## 一、实验课定位

这是实验线的收束课。目标不是追求漂亮结果，而是训练学生把前四节实验中的代码定位、日志、表格和解释整理成一份合格的最小复现实验包。

## 二、本节实验目标

完成本节后，学生应能够：

- 定义一个可否定的小型系统问题。
- 设计 baseline 与对照组。
- 形成完整的运行记录、结果表和解释文档。
- 清楚说明“观察到现象”和“证明机制收益”的边界。

## 三、实验材料

- 理论配套：`tutorials/nano-vLLM实验与Tutorials/Tutorial_05_指标观测与最小复现实验.md`
- 参考代码：`code/nano-vllm-hust/bench.py`
- 学生练习：`code/nano-vllm-hust/student_exercises/bench.py`
- 作业包：`code/nano-vllm-hust/assignments/tutorial_5_spring-2026/`
- 结果汇总脚本：`code/nano-vllm-hust/scripts/teaching/collect_benchmark_results.py`

## 四、课前检查

- 学生已完成前四节实验，手头已有代码地图、阶段日志、batch 日志或状态观测表。
- 教师已讲过 baseline、对照组、warmup、重复实验和结论边界。
- benchmark 运行入口可用。

## 五、建议课时安排

- 10 分钟：说明最小复现实验包的结构。
- 20 分钟：学生确定本次要验证的小问题。
- 25 分钟：运行 baseline 与对照。
- 20 分钟：整理结果表和异常记录。
- 10 分钟：写结论边界。
- 5 分钟：说明提交与汇总方式。

## 六、本节核心问题

怎样把一次课堂运行整理成别人可以复查、可以复跑、也可以否定的实验记录？

## 七、实验步骤

### 步骤 1：定义一个可否定问题

从前四节实验中选一个小问题，例如：

- 长 prompt 是否显著抬高 TTFT。
- 某个 batch limit 是否改善吞吐但恶化短请求等待。
- 上下文变长是否通过状态驻留抬高 queue wait。

要求问题必须具体、可检验，不能写成“看看系统表现”。

### 步骤 2：设计 baseline 与对照

至少包含：

- 一个 baseline
- 一个改动配置或改动策略
- 一组固定 workload
- 三次重复运行或等价稳态统计

### 步骤 3：固定实验记录结构

建议实验包至少包含：

- `README.md`：实验问题、命令、环境说明
- `results.csv`：核心指标
- `notes.md`：异常、失败、解释
- 原始日志摘录或截图

### 步骤 4：运行并记录结果

建议表格：

| experiment | workload | policy/config | run_id | TTFT | throughput | queue_wait | notes |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |

### 步骤 5：写边界说明

每份报告必须明确写出：

- 哪个结果支持当前解释。
- 哪个结果会直接推翻当前解释。
- 哪个变量没有被完全控制住。

## 八、课堂讨论问题

1. 你的结果真正支持了什么，不支持什么。
2. 哪个变量控制得最好，哪个最弱。
3. 哪个异常值最值得追查，而不是直接删掉。

## 九、常见错误

- 只有结果表，没有运行命令。
- 只有最好的一次结果，没有对照或重复。
- 只写“性能提升了”，没有写边界与失败条件。
- 把观察结果直接写成机制已经被证明。

## 十、课后提交要求

1. 一份最小复现实验说明。
2. 一张结果表。
3. 一段 500-800 字分析，写清结论边界。
4. 如有需要，附原始日志或截图。

## 十一、评分重点

- 记录是否完整。
- baseline 与对照是否清楚。
- 是否有诚实的边界说明。
- 结果是否回到控制点和系统对象。

## 十二、与课程项目的衔接

本节提交物应直接进入课程项目开题或结题材料，而不是另起一套格式。教师可要求学生在课程项目第一页引用本节实验编号和结果表编号。
