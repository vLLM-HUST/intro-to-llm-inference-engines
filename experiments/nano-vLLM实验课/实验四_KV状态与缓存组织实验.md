# 实验四：KV 状态与缓存组织实验

## 一、实验课定位

本节实验把 KV 从“attention 的中间量”提升为“推理系统中的长期状态对象”。课堂重点是状态如何生成、驻留、扩展和释放，以及这种状态组织如何反过来约束并发和调度。

## 二、本节实验目标

完成本节后，学生应能够：

- 画出 KV 或请求状态对象的生命周期。
- 指出状态与请求、调度、并发之间的关系。
- 用一次状态容量观察说明“长上下文为何会压缩系统弹性”。
- 区分 observe-only 探针和真实复用收益。

## 六、本节核心问题

为什么很多看起来像“调度问题”或“延迟问题”的现象，根上其实是状态驻留和容量问题？

## 七、实验步骤

### 步骤 1：找出状态生命周期

要求学生定位或近似定位以下事件：

1. prefill 产生 KV 或等价状态。
2. decode 继续读取和追加状态。
3. 请求完成后释放状态。
4. 多请求并发时状态如何绑定到 request_id。

### 步骤 2：设计状态容量观察

至少准备三类输入：

- short_ctx：较短上下文
- long_ctx：较长上下文
- mixed_ctx：长短上下文混合

建议记录以下量：

- 当前存活请求数
- 每请求估计状态规模
- 总状态对象数或总块数
- TTFT
- queue wait

### 步骤 3：整理因果链

要求每位学生至少写出一条明确因果链，例如：

```text
上下文变长 -> 状态驻留增大 -> 可并发请求减少 -> 等待时间上升 -> TTFT 变差
```

### 步骤 4：可选进阶任务

二选一：

1. 实现一个最小状态统计器。
2. 实现一个 observe-only 的前缀命中探针。

如果选择探针，报告中必须明确写成：

- 这是潜在重叠信号。
- 这不是已经兑现的真实复用收益。

## 八、课堂讨论问题

1. KV 为什么不是“用完即弃的临时量”。
2. 为什么状态压力会先改变并发弹性，而不只是改变某个局部算子的时间。
3. 在你的实验里，最能说明状态问题的观测量是什么。

## 九、常见错误

- 把 KV 只写成 attention 的中间结果。
- 只看显存或块数，不解释它如何影响并发和等待。
- 用 observe-only 探针结果直接宣称有真实复用收益。
- 没有说明状态规模估计的近似边界。

## 十、课后提交要求

1. 一张 KV 生命周期图。
2. 一张状态容量观察表。
3. 一段 500-800 字分析，说明状态如何约束系统能力边界。
4. 如果做了探针，附一段明确的 truthfulness 说明。

## 十一、评分重点

- 是否建立了状态视角，而不是仍停留在单次计算视角。
- 因果链是否清楚。
- 是否诚实区分观测信号和真实收益。
