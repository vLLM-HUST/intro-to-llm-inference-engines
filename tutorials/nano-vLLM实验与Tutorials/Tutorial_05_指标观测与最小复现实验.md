# Tutorial 5：指标观测与最小复现实验

## 本次联动位置

- 对应讲次：第 11 讲“实验方法与可验证性”。
- 对应实验：`experiments/nano-vLLM实验课/实验五_指标观测与最小复现实验.md`。
- 参考代码：`code/nano-vllm-hust/bench.py`。
- 本 tutorial 负责实验可信性的问答辨析，具体实验包结构和运行要求见实验课文档。

## 目标

本 tutorial 的目标不是追求漂亮曲线，而是训练学生判断什么样的实验才算可信。学生完成后应能说明：哪些证据足以支撑结论，哪些还不够。

## 本 tutorial 不做什么

- 不在这里给出 benchmark 操作步骤。
- 不直接要求打包提交实验结果。
- 不把“如何跑”与“为什么这样跑”混写在一起。

## 核心概念

- 结果表不是实验本身，实验的核心是变量控制、对照设计和边界说明。
- 观察到现象不等于证明机制收益。
- 一个好实验必须允许自己被否定。

## 必答问题

1. 为什么单次最好结果通常不能支撑系统结论。
2. 为什么 baseline 和对照组是实验解释的前提。
3. 为什么“哪个结果会推翻当前解释”必须在实验前就写出来。

## 课堂追问

- 如果一个同学的结果很好看，但没有说明 workload 构造方式，是否还能算可信。
- 为什么系统课里“负结果”不应该被自动视为失败。
- 如果日志、表格和解释互相对不上，应该优先信哪一层证据。

## 推荐阅读与观察

- `code/nano-vllm-hust/bench.py`
- 课程中关于 baseline、对照组、warmup、稳态与回归的讲义部分

观察重点：

- benchmark 代码里哪些变量最容易改变结果解释。
- 结果打印与实验设计之间是什么关系。
- 为什么实验方法本身也是系统能力的一部分。

## 推荐产出

- 一份实验可信性检查表。
- 一段 400-600 字说明：你认为一份结果表要满足什么条件才足以进入课程项目。

## 本 tutorial 应回答的问题

- 为什么课程把“实验方法”单独拿出来讲，而不是放在最后附录里。
- 为什么“可复现”不是把命令贴出来就结束了。
- 为什么系统研究必须同时接受正结果和负结果。
